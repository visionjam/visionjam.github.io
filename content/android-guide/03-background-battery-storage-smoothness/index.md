## 3. 后台、自启动与省电

### 3.1 Android 后台机制速览

理解这几件事，能避免大部分“省电玄学”：

- **进程状态**：前台、可见、服务、缓存。缓存进程不是“浪费内存”，它们让下次启动更快；内存不足时系统会按优先级回收。
- **Doze**：手机长时间静止、熄屏后进入深度休眠，网络和任务被推迟到维护窗口。
- **App Standby**：系统按使用频率给应用分桶（active / working set / frequent / rare / restricted），越不常用限制越强。
- **前台服务**：带常驻通知的后台服务。Android 14+ 对前台服务类型有更严格的要求，滥用会耗电并触发通知。
- **JobScheduler / AlarmManager**：延迟任务和定时任务。精确闹钟权限收紧后，普通应用不能随意精确唤醒。

**为什么“杀后台”反而可能更耗电**：应用被杀死后，推送需要重新注册、数据需要重新同步、冷启动更慢；如果它还有自启动或关联启动，会反复被拉起，形成“杀死—重启—再杀死”的循环。

### 3.2 HyperOS 3 的自启动与耗电管理

以 HyperOS 3 为例，重点关注三处（路径可能随版本略有差异）：

1. **自启动管理**：设置 → 应用设置 → 授权管理 → 自启动管理。按应用关闭“自启动”和“关联启动”。
2. **应用耗电管理**：设置 → 电池 → 应用耗电管理。点进应用，选择“无限制 / 智能限制 / 严格限制”。
3. **锁屏清理 / 省电策略**：部分版本在手机管家或电池设置里有“锁屏清理”“神隐模式”一类开关。**如果你依赖即时通知，建议关闭锁屏清理**，改用按应用限制。

三档耗电策略怎么选：

| 策略 | 行为 | 适合 |
| --- | --- | --- |
| 无限制 | 后台基本不受限，可长时间运行 | 即时通讯、邮件、闹钟、健康监测、查找设备 |
| 智能限制 | 系统根据使用习惯调度 | 大多数日常应用 |
| 严格限制 | 后台活动被强力限制，可能延迟通知 | 购物、资讯、游戏、一次性工具 |

> 只给必须及时响应的应用设“无限制”；不确定的应用先用“智能限制”。

另外：

- **应用双开/手机分身**会复制一套应用进程，不用的分身及时关闭。
- **省电模式/超级省电**会限制性能、刷新率和后台，按需开启，不要长期常开。
- **小米云服务/查找手机**是有用的安全功能，建议保留“查找设备”；云同步按需开启。

### 3.3 通用 Android 的电池优化

- **电池优化白名单**：设置 → 应用 → 选择应用 → 电池 → 不受限制。只给必须及时响应的应用，不要全部放行。
- **自适应电池**：保持开启，让系统学习使用习惯。
- **数据节省程序**：限制后台移动数据，适合流量敏感的用户。
- **后台数据限制**：应用信息 → 移动数据与 Wi-Fi → 关闭“后台数据”，比直接杀进程更温和。
- **Restricted**：Android 的“受限”比“优化”更强，可能导致通知延迟，慎用。

### 3.4 adb 辅助（可选）

系统电池面板足够定位大多数问题。如果你已经会 adb，可以看：

```bash
adb shell dumpsys battery
adb shell dumpsys meminfo | head -n 40
```

不展开唤醒锁、Job、闹钟的复杂命令；需要时查官方文档。

### 3.5 应用分级策略

| 应用类型 | 自启动 | 关联启动 | 电池策略 | 通知 |
| --- | --- | --- | --- | --- |
| 即时通讯/邮件/闹钟/健康 | 允许 | 默认禁止 | 无限制（仅这类） | 开（含验证码/交易提醒） |
| 银行/支付/认证 | 允许 | 默认禁止（支付/登录异常时临时开） | 智能限制 | 开（保留交易/安全/验证码，关营销） |
| 购物/外卖/资讯/短视频 | 禁止 | 禁止 | 智能限制或严格限制 | 关营销 |
| 游戏/视频 | 禁止 | 禁止 | 智能限制 | 关 |
| 导航/打车 | 禁止（用时手动开） | 禁止 | 智能限制 | 保留行程提醒 |
| 一次性工具 | 禁止 | 禁止 | 严格限制 | 关 |

> “智能限制”“严格限制”是 HyperOS 的名称；原生 Android 对应“优化/受限”，而且没有统一的自启动/关联启动开关，这两列在原生上跳过，改用电池优化/后台限制（3.3），或 Shizuku/Hail。
> 微信、QQ 等即时通讯按第一行处理，不要因为它们在“社交”分类里就禁自启动。
> 第三方闹钟/提醒（例如WakeUp课程表）还需要“闹钟和提醒”特殊权限（Android 12+）；只设电池策略不能保证准时。路径：应用信息 → 特殊权限/闹钟和提醒（名称随版本变化）。

这张表是起点，不是教条。改完至少观察两天，确认消息、闹钟、验证码、支付提醒没有延迟。

#### 3.5.1 不要过度限制的应用

下面这些应用，限制过头会直接影响日常；其中即时通讯/闹钟/健康类直接设“无限制”，其他先“智能限制”，观察两天：

- **即时通讯/邮件**：微信、QQ、WhatsApp、Discord、飞书、企业微信、QQ邮箱、Gmail、Thunderbird。
- **闹钟/日历/提醒**：小米时钟、小米日历、WakeUp课程表。
- **支付/认证**：支付宝、银行 App、PayPal、Microsoft Authenticator、Bitwarden。
- **健康/家庭**：小米健康、米家告警、查找设备。
- **系统关键**：输入法、桌面、电话/短信、安全中心、包安装器、权限控制器。

几条判断标准：

- **验证码**可能走短信、微信、银行 App 推送或邮箱；不要为了省电关闭短信权限或全部通知。先确认验证码来源，再决定限制哪一项。
- **银行/支付/认证类**要保留“交易通知/安全提醒/验证码”渠道，关闭营销；不要只留一个模糊的“重要”档。
- **第三方闹钟/提醒**还要允许“闹钟和提醒”特殊权限（Android 12+），否则电池策略再宽也可能不准。
- **关联启动**默认禁止；只有当你明确需要 A 拉起 B 完成功能时才允许。支付/登录/分享被拦截时，先临时打开对应应用的关联启动，完成后再关；不确定就禁止。
- **“无限制”和“不受限制”是同一件事**：HyperOS 叫“无限制”，原生 Android 叫“不受限制”，只给必须及时响应的应用。
- 改完观察 48 小时；出现通知延迟、闹钟不响、验证码收不到，先把该应用从“严格限制”放宽到“智能限制”，仍不行再设“无限制”。

### 3.6 常见误区

- **一键清理/内存加速**：现代 Android 不需要；频繁清理会让应用反复冷启动，反而更耗电。
- **杀后台省电**：对即时通讯、邮件类应用往往适得其反。
- **电池校准**：现代手机不需要定期把电放光；经常深度放电反而伤电池。
- **整夜充电**：现代充电管理会在接近满电时降速；真正伤电池的是高温，避免边充边玩大型游戏。
- **关闭 5G 一定省电**：取决于信号覆盖。弱 5G 可能比强 4G 更耗电，反之亦然，按实际场景测试。
- **省电模式常开**：会限制性能和刷新率，按需使用。
- **黑域/冰箱/绿色守护**：现代系统 + Shizuku 工具更可控。


## 4. 存储与文件管理

### 4.1 先看存储构成

设置 → 存储，先看分类：应用、图片、视频、音频、文档、系统、缓存。点进“应用”按大小排序，通常能发现几个“吃存储大户”。

### 4.2 清理原则

1. **先备份再删**：照片、聊天记录、下载的文档，确认有副本再清理。
2. **用清浊清理手机存储**：先按第 4 篇 6.7 启动 Shizuku，再在清浊里授予 Shizuku 权限，导入社区里可信的清理任务/规则；先预览再执行。
3. **缓存 ≠ 垃圾**：清缓存会让应用重新下载/重建，只有应用异常或空间极度紧张时才需要。
4. **清除数据要谨慎**：应用数据包含登录状态、聊天记录、设置；清之前先导出。
5. **保持余量**：至少留 10%–15% 空间，系统更新和文件系统需要缓冲。
6. **定期卸载不用的应用**：比清缓存更有效，也更安全，半年不打开一次为基准。当然有特殊意义和应急软件例外。

> 清浊（`com.farplace.qingzhuo`）通过 Shizuku 获得 shell 权限，能清理系统清理器够不到的缓存、空文件夹和大文件。只装清浊一个清理工具，不要叠加其他“清理大师”；只清缓存/空目录/大文件，不要清应用数据、聊天记录和 Download 里的重要文件；社区任务来源要可信，涉及应用数据的项不要勾。

### 4.3 微信/QQ 专项

微信通常是最大的存储占用者。**顺序很重要：先备份，再清理。**

**第一步：备份**

1. 在电脑上登录同一账号的微信 PC 版，确保手机和电脑在同一网络。
2. 微信 PC 版 → 左下角菜单 → 备份与恢复 → 备份聊天记录到电脑。
3. 等待完成，记录备份的大小/文件数量；**不要试图直接打开备份文件**——微信 PC 备份是加密专有格式，只能在微信里恢复到手机。最稳妥的是做一次恢复演练（恢复到备用机/模拟器），至少确认备份任务成功。
4. 把备份目录再复制一份到另一块硬盘、NAS 或可信云盘；只留 PC 上一份，重装系统/硬盘故障会一起丢。
5. 重要的图片/视频/文件，单独导出到电脑或 NAS；聊天记录备份通常不包含收藏、朋友圈、小程序数据和部分双开账号。
6. 如果备份失败，先解决备份问题（网络、空间、版本），不要继续清理。

**第二步：清理**

- 微信 → 我 → 设置 → 通用 → 存储空间 → 管理，按聊天/类型清理图片、视频、文件。
- 关闭“移动网络下自动下载”照片/视频，减少流量和缓存。
- 手机管家里的“微信专清”可以辅助（小米/部分 ROM；原生 Android 用微信自带存储管理即可），但先预览清理项；没有备份不要用。
- **不要**用“清除数据”或 `pm clear com.tencent.mm`：这会清空登录状态和全部聊天记录，且很难恢复。
- **优先**用软件内部“清除数据”的功能。

QQ 类似：先用 QQ PC 版备份/迁移聊天记录，再清理缓存和聊天文件；关闭自动下载；重要文件单独导出。

> 微信删除的聊天媒体通常没有可靠的回收站；确认备份完成后再删。

### 4.4 照片与视频

- **云备份**：小米云、Google Photos、自建 NAS/相册服务都可以；选原图还是压缩版，按需求决定。
- **回收站**：删除后通常有 30 天回收站，确认无误再清空。
- **重复/截图/录屏**：定期清理截图、屏幕录制、重复照片。
- **大视频**：用文件管理器按大小排序，先处理几 GB 的视频。
- **批量备份**：`adb pull /sdcard/DCIM/Camera ./Camera`，确认文件完整后再删除手机端。

### 4.5 文件传输与备份

- **局域网**：LocalSend 适合临时传文件；Syncthing-fork 适合多设备持续同步。
- **远程**：Tailscale 组网后访问家里的 NAS/电脑；注意只开放必要端口。
- **应用数据**：`adb backup` 在新版 Android 上已受限甚至不可用；优先用应用自带的导出/云备份。Shizuku 只提供 shell 权限，不能读取其他应用的私有数据；完整应用数据备份通常需要应用自身导出或系统级备份方案，风险更高。
- **备份验证**：备份完随机打开几个文件确认可读，不要只看“传输完成”。

### 4.6 应用数据与缓存

- **清除缓存**：应用信息 → 存储 → 清除缓存；不会退出登录。
- **清除数据**：会删除登录状态和本地数据；相当于重装，慎用。
- **`pm clear`**：`adb shell pm clear <包名>` 会清空应用数据，执行前必须确认已备份。
- **空间不足时的顺序**：卸载不用应用 → 清大文件/视频 → 清聊天缓存 → 清应用缓存 → 最后才考虑清数据。

### 4.7 存储维护清单

- 每周：看一次存储余量，清理下载目录和截图。
- 每月：备份照片，清理微信/QQ 大文件，检查“应用”占用排行。
- 每季度：卸载三个月没打开的应用，审查权限和通知。


## 5. 流畅度与显示

### 5.1 卡顿从哪里来

卡顿不一定是“性能不够”，常见原因：

- CPU/GPU 瞬时负载高（游戏、相机、视频导出）；
- 内存压力导致应用被回收，切换回来要重载；
- 存储 I/O 慢（空间不足、碎片、后台下载）；
- 温控降频（边充边玩、夏天户外）；
- 动画与刷新率不匹配；
- 后台同步、推送、扫描在同一时间集中发生。

排查顺序：先看“显示刷新率”和“GPU 渲染模式分析”，再看电池温度、`top` 和 `dumpsys meminfo`，最后才怀疑“系统负优化”。

### 5.2 动画

开发者选项里把三项动画缩放设为 0.5x。可以直接在设置中调节，也可以像下边一样用adb命令调节。

先记下原值（有些 ROM 默认不是 1.0）：

```bash
adb shell settings get global window_animation_scale
adb shell settings get global transition_animation_scale
adb shell settings get global animator_duration_scale

# 设置为 0.5x
adb shell settings put global window_animation_scale 0.5
adb shell settings put global transition_animation_scale 0.5
adb shell settings put global animator_duration_scale 0.5
```

恢复原值：

- 如果 `get` 返回 `null`，说明没有覆盖值，用 `settings delete` 删除即可，不要写入 `null`；系统默认通常是 1.0，删除后按默认值生效。
- 如果返回数字，把数字填回。

```bash
# 原值为 null 时
adb shell settings delete global window_animation_scale
adb shell settings delete global transition_animation_scale
adb shell settings delete global animator_duration_scale

# 原值为数字时（示例：1.0）
adb shell settings put global window_animation_scale 1.0
adb shell settings put global transition_animation_scale 1.0
adb shell settings put global animator_duration_scale 1.0
```

0.5x 让过渡更快，但保留反馈；设为 0 会让一些界面的进入/退出显得突兀，也可能影响依赖动画回调的应用。

### 5.3 刷新率

- 120Hz 更顺滑，但更耗电；智能切换可能在静止/低负载时降到 60Hz，具体取决于厂商策略。
- 省电模式、部分游戏、视频播放可能强制 60Hz；用“显示刷新率”确认实际值。
- 部分 ROM 支持按应用设置刷新率；优先用系统设置。没有的话，不要用第三方工具强行锁帧，可能造成撕裂或耗电异常。
- **仅 AOSP/类原生**：`peak_refresh_rate` / `min_refresh_rate` 是“允许范围”，不是锁死 120Hz；实际刷新率仍由系统和应用决定。HyperOS 3 很可能忽略这些值（小米使用自己的刷新率设置），优先用系统设置，不要照抄命令。

```bash
# 先记原值（可能返回 null）
adb shell settings get system peak_refresh_rate
adb shell settings get system min_refresh_rate

# 设置范围（仅 AOSP/类原生示例）
adb shell settings put system peak_refresh_rate 120.0
adb shell settings put system min_refresh_rate 60.0

# 原值为 null 时：删除覆盖值
adb shell settings delete system peak_refresh_rate
adb shell settings delete system min_refresh_rate

# 原值为数字时：填回原值
adb shell settings put system peak_refresh_rate <原值>
adb shell settings put system min_refresh_rate <原值>
```

改完观察耗电和发热；如果系统设置里已有刷新率选项，优先用它。

### 5.4 内存与内存扩展

- 12GB/16GB 的机型，日常不需要“内存清理”；缓存内存会自然被系统利用。
- **内存扩展（虚拟内存）**用存储空间充当 swap（HyperOS/部分 ROM；原生 Android 通常只有 ZRAM，没有这个开关，跳过）。它可能让后台保留更多应用，但也增加存储 I/O 和写入；是否开启取决于机型、存储速度和你的使用习惯。大内存机型可以关闭或选最小档，但没有“一定更稳”的结论，建议自己对比一周。
- 判断是否需要更多内存：看**应用是否频繁重载、冷启动是否变慢、LMK 是否频繁回收**，而不是看“剩余内存”数字。`dumpsys meminfo` 里的 `MemFree`/`Cached` 只能作参考，不能单独作为好坏标准；想看当前 LRU/缓存状态可以用 `adb shell dumpsys activity lru | head -n 40`。
- 不要同时开多个“内存优化”工具。

### 5.5 后台限制与 LMK

开发者选项里的“后台进程限制”是调试工具，不是日常省电开关。长期开启会导致：

- 应用频繁被杀、冷启动变慢；
- 通知延迟或丢失；
- 输入法、桌面、相机等系统组件被误杀；
- 系统反复拉起进程，反而增加耗电。

正确做法：用第 3 节的按应用电池策略，而不是全局限制进程数。

### 5.6 游戏与温控

- 边充边玩大型游戏是发热大头；能避免就避免，至少不要用厚壳。
- 性能模式/游戏模式按需开，不要 24 小时常开。
- 稳定帧率比最高帧率更重要；过热降频时，降画质/帧率比“去温控”安全。
- **不要关闭温控保护**。温控是防止硬件损坏的最后一道防线。
- 游戏空间里的“性能增强”“网络加速”按需使用（小米/部分 ROM；原生 Android 用游戏仪表盘或跳过），注意是否同时提高了功耗。

### 5.7 系统更新

- 优先稳定版；大版本更新后等几天，看看社区反馈再更。
- 更新前备份，保持 10GB 以上空闲空间，电量 50% 以上。
- 安全补丁建议保持较新；不要为了“省电”长期停留在有已知漏洞的旧版本。
- 不要用来路不明的“更新阻断”工具（或者adb停用卸载掉更新程序），除非你清楚安全代价。
- **大版本不必追新**：厂商的云端配置/运营策略（俗称“云控”）会影响体验，大版本更新也可能带来新的广告位、功能变化和兼容性问题。比如一台发布时是 Android 15 的手机，两年维护期内通常会经历 Android 16；如果 Android 17 发布后厂商的维护重点转移，停在 Android 16 的最后一个稳定版，通常比追新更稳。版本不是越高越好，稳定、可控、能持续拿到安全补丁更重要。


### 5.8 桌面与动态效果

- 减少动态壁纸、过多小组件、复杂图标包。
- 负一屏、搜索推荐、文件夹推荐按需关闭（见 2.1；HyperOS/部分启动器，原生没有就跳过）。
- 深色模式在 OLED 上更省电；自动亮度通常比手动固定亮度更省心。

### 5.9 开发者选项里的陷阱

- **不保留活动**：只用于调试，日常开启会让应用每次切换都重载。
- **强制 GPU 渲染 / 4x MSAA**：老技巧，现代应用不一定受益，可能更耗电。
- **停用 HW 叠加层**：只用于排查渲染问题，不要长期开。
- **更改 DPI/分辨率**：可能导致布局错乱、应用不兼容。先在电脑上执行 `adb shell wm size` / `adb shell wm density` 记下原值；出问题用 `adb shell wm size reset` / `adb shell wm density reset` 恢复。改之前确保电脑和 adb 可用。
- **显示布局边界/指针位置**：调试用，平时关掉。
