在[Hello,world!](/posts/hello-world/)里我说过，写作会迫使我把「大概也许可能或许知道」变成「真正想明白了」。这篇接着写具体怎么做。

## 为什么写

写作首先是给自己看的。一个念头在脑子里转的时候是模糊的，落到句子里，哪里没想明白就藏不住了。

> 我写作，完全是为了弄清楚我在想什么、我在看什么、我看到了什么，以及这意味着什么。
>
> —— 琼·狄迪恩，[《我为什么写作》](https://www.nytimes.com/1976/12/05/archives/why-i-write-joan-didion.html)

这句话几乎说完了我的理由。至于发表出来，是顺带的：如果能帮到别人，或者让人产生一点不同意见，都算额外收获。~~影响力也是一种力量。~~

还有一点要补充的是要对抗语言腐败。随着我国9年义务教育事业高歌猛进，大量的文盲被训练出来了等价于革命年代扫盲班夜校知识水平，这些人语言能力底下，熟练运用主谓宾定状补和标点符号的人口十不存一。很多言语本来的意思被不可逆不合理简化压缩，扭曲坍缩，外延抽象等，变成一副不可名状的样子，严重污染公共舆论场和认知。

例如到底斩杀线的定义是啥？什么是“学生思维”？做题蛆又具体是指什么？
知乎金句“先问是不是，再问有没有”。如果一个概率你连定义都拎不清，就请你不要再掉书袋了。止增笑耳。

为了对抗这种现象，我特意尽量用大白话和不做作拗口的文字来写博客。你知道吗？其实字典也是这样编写的，先用一些基础的字词来相互定义，再用这些基础字词来延伸常见的概念，以此类推。**简单的东西总是顽固的。**

希望这些结实的东西能对抗现如今下沉到底的互联网的傻逼共振现象。

## 两种写法

我写东西大概分两种模式。用哪种，取决于我对要写的事到底有多熟。

### 一、有积累的长文：先讲一遍，再让 AI 起稿

这种文章的前提是：我自己有思路，也完整走过一遍。折腾某个工具、踩过一轮坑、把一件事从头到尾做成，这类内容才有资格这么写。没有亲身经历，AI 生成的东西会空。

流程大致是：

1. **收集材料**：命令、截图、报错、结果，先放在一起。
2. **语音输入**：对着手机把过程讲一遍，不修饰，想到哪说到哪。
3. **整理大纲**：把口述内容切成几节，标出先讲什么、后讲什么。
4. **AI 生成初稿**：把大纲和材料一起交出去，要求它按大纲写，不许补充我没给的事实。
5. **人工审核**：这一步不能省。

审核主要看四件事：事实有没有错；命令和链接能不能跑通、点开；有没有「正确但不像我」的句子；语气是不是我自己的。AI 很擅长把话说得四平八稳，也很擅长把细节写得像真的。前者要删，后者要查。

也许以后文字量上去以后能让AI蒸馏我的语言风格，做永远活在电子世界的幽灵。

### 二、纯手搓：短、快、有脾气

另一种完全不借助 AI，想到什么写什么。通常很短，可能只有几百字，语言风格明显——骂人、阴阳怪气、直球，都是我表达的一部分。这类文章不追求结构完整，追求的是当时的那口气。发出去可能得罪人，但那也是自己的声音。

> 写不出的时候不硬写。
>
> —— 鲁迅，[《答北斗杂志社问》](https://zh.wikisource.org/wiki/答北斗雜誌社問)

手搓的前提是有话想说。没话的时候硬凑，写出来的东西自己都不想看。所以我不给自己定更新频率，有就写，没有就空着。

## 工具

工具越少越好，能写字就行。

- **电脑**：VS Code 加 Markdown 插件，成稿、预览、改错别字都在这里完成。插件提供预览和快捷键，[官方文档](https://code.visualstudio.com/docs/languages/markdown)里有说明。
- **手机**：[Obsidian](https://obsidian.md/) 用来记长一点的草稿，[Markor](https://github.com/gsantner/markor) 用来快速记一句话。两个都直接读写 Markdown 文件，不用导出。
- **格式**：统一用 Markdown，遵循 [CommonMark](https://commonmark.org/) 的写法。不在平台编辑器里直接写长文——平台会变，文件还在自己手里。

## 发布

发布是纯技术流程，交给工具。这部分我不用管内容，只管别把不该公开的东西推上去。

- **新建文章**：`python tools/blog.py new`，生成 `content/posts/<slug>/index.md` 的 page bundle。
- **配图**：图片放文章同目录，正文用相对路径引用；需要图注时用 `figure` 短代码。
- **本地预览**：`hugo server -D`，`-D` 让草稿也能看到。
- **发布**：`python tools/blog.py publish`（或 `publish.bat`）会依次做构建、隐私扫描、确认，然后只提交 `content/` 下的改动并推送。隐私扫描拦截本机路径、代理地址、密钥这类内容，新增图片会单独列出来人工确认。
- **部署**：推送 `main` 后，GitHub Actions 用 [Hugo](https://gohugo.io/) 构建并部署到 [GitHub Pages](https://docs.github.com/en/pages)。RSS、搜索索引和标签页都会跟着更新。
- **别名**：frontmatter 里的 `aliases` 可以给文章加备用地址。这篇设了 `/posts/how-i-write-blog/`，访问它会自动跳到当前链接，[Hugo 的文档](https://gohugo.io/content-management/urls/#aliases)里有完整用法。

主题是 [PaperMod](https://github.com/adityatelange/hugo-PaperMod)，站内还有[标签](/tags/)、[归档](/archives/)、[搜索](/search/)和 [RSS](/index.xml) 可以浏览。

## 最后

工具和流程的存在，是为了让开始写这件事的门槛低一点。真正难的不是排版、不是发布，是坐下来把一句话写完整。

别等想清楚再写。写的过程本身，就是在想清楚。
